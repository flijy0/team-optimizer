# TeamOptimizer

FastAPI + PostgreSQL + OR-Tools CP-SAT.

## Запуск
```
docker compose up -d db
pip install -r requirements.txt
uvicorn app.main:app --reload      # http://localhost:8000
```
Строка подключения — `DATABASE_URL` (по умолчанию `postgresql://team:team@localhost:5432/team`). Схема и демо-данные создаются при старте.

## Модель
`x[человек, проект] ∈ {0,1}`; каждый в ровно одной команде; размер команды ∈ [min, max].
Цель: `max Σ w_k · score_k` (веса нормируются).

- skills = Σ min(D[j,s], Σ x·Cap[p,s]) / Σ D — покрытие потребности
- exp = 1 − Σ_j |Σ_{p∈j}(exp_p·N − Σexp)| / Σ_p |exp_p·N − Σexp| — каждая команда получает «справедливую долю» опыта
- pref = доля людей, чьё предпочтение входит в навыки их проекта
- size = 1 − (макс. размер − мин. размер) / (max − min)

Потребность `D[j,s]`: если у проекта есть задачи — Σ(часы · приоритет / 3) по задачам навыка; если нет — 16 · недель на каждый навык проекта.
Ёмкость `Cap[p,s]` = часы/нед · недели · (опыт / 5) / число навыков человека.

## Воспроизводимость и проверка
- вход канонизируется (сортировка, нижний регистр) и хэшируется; решатель работает в 1 поток с фиксированным `seed`;
- каждый запуск пишется в `runs` (вход, результат, хэши); `POST /api/runs/{id}/replay` пересчитывает и сравнивает хэш решения;
- `evaluate()` независимо от модели пересчитывает ограничения и оценки по готовому назначению;
- `OPTIMAL` — оптимум целочисленной модели (коэффициенты округляются до 1e-6). При `FEASIBLE` (лимит времени) воспроизводимость не гарантируется.
- Гарантия действует для одной версии OR-Tools и платформы.
